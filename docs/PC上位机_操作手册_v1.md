- 适用版本：PC 控制台 1.0.0（`pc_console/`）＋ Pi 网关 1.0.0（`ros2_ws/src/raspbot_console/`）
- 适用系统：PC（Windows 10/11，Edge/Chrome）＋ Raspberry Pi 5（Ubuntu / ROS 2 Lyrical）
- 依据契约：`docs/PC上位机_设计文档_v1.md`（Wire API v1，**冻结**）。本文面向使用者；
  接口字段/状态机细节以设计文档为准，本文不复述完整协议。
- 配套文档：`tools/console/README.md`（部署与验收脚本）、`pc_console/README.md`（PC 程序细节）、
  `docs/PC上位机_验收记录_2026-11-24.md`（验收证据与已知偏差）

## 1. 产品定位与安全边界

### 1.1 它是什么

PC 上位机控制台是一个**局域网内的观察 + 控制台**：

- **观察**：实时 2D 地图、机器人位姿/朝向、激光扫描点、导航路径、速度、诊断、节点/话题健康、连接状态。
- **建图**：一键开始/停止建图；建图中可遥控并实时看到地图增长；一键保存为 PGM+YAML。
- **导航**：选择已保存地图 → 设置初始位姿 → Nav2 激活 → 点击地图设目的地 → 查看剩余距离/状态 → 取消/重试。
- **手动控制**：键盘 WASD/QE 或虚拟摇杆遥控（麦轮全向）、速度档位、松手即停、软件急停。
- **附加**：蜂鸣器/RGB 灯/云台、事件日志、会话日志、地图列表与预览、无硬件演示模式。

架构：浏览器 → PC 端 `pc_console`（本地静态资源 + `/api/*` 反向代理 + `/local/*` 配置）→
Pi 端 `raspbot_console` HTTP/SSE 网关（:8080）→ ROS 2 话题/Nav2。PC 端**不安装 ROS**，
两端只通过 HTTP/SSE 契约通信。

### 1.2 明确不做

- **不做视频/图传**：SLAM 场景下 UI 主体是 2D 地图，相机与 Hailo 感知仍由 ROS 侧按原方式局部使用。
- **不做公网远控**：网关无 TLS/账号体系，仅限可信内网；禁止把 8080 端口映射到公网。
- **不承诺无编码器下的精确走位**：定位精度边界见主 README 与设计文档 §9。
- **不修改** `ros2_ws/CONTRACTS.md` 已冻结的话题/TF 契约；网关不新增任何 TF 发布者。

### 1.3 必须知道的硬件边界（UI 与文档都会提示）

| 边界 | 后果 | 应对 |
|---|---|---|
| **无轮编码器** | `/odom` 是开环积分，长距离会漂移；导航定位依赖 AMCL 激光修正 | 看 UI 的定位来源（map/odom），长距离导航分段跑、必要时重设初始位姿 |
| **2D 雷达扫描面离地约 74 mm** | 看不见低矮障碍、玻璃/镜面、悬空物；只扫一个平面 | 场地清障、限制速度、全程有人监护；不要把玻璃墙当边界 |
| **无悬崖/跌落检测** | 台阶、桌边、斜坡不会自动停车 | 禁止在有跌落风险场地运行；必要时物理围挡 |
| **限速默认** | `max_linear=0.30 m/s`、`max_lateral=0.30 m/s`、`max_angular=1.5 rad/s` | 网关会 clamp；调试可改 `--max-linear` 等参数，但不要超过场地安全值 |
| **500 ms 遥控看门狗** | 超过 0.5 s 没收到遥控帧就自动零速（设计行为） | Wi-Fi 弱时会「一顿一停」属正常保护；改善网络而非关看门狗 |
| **Nav2 不 autostart** | 导航模式必须先设初始位姿，再由网关按顺序激活（冷启动 20–60 s） | 看「正在激活导航（步骤 x/6）」进度，不要重复点击 |

> **一句话**：这是「有人监护下的室内低速实验控制台」，不是无人值守/载人/室外产品。

## 2. 前置条件

### 2.1 PC 端

- Windows 10/11（64 位），安装 **Python 3.10+**（仓库实测 Python 3.14.7；仅用标准库，无需 pip 安装任何包）。
- Edge 或 Chrome 浏览器（最近两年版本；`--browser app` 会优先生成 Edge/Chrome 应用窗口）。
- 真车模式：PC 与 Pi 在同一局域网，可访问 Pi 的 8080 端口。

### 2.2 Pi 端

- Raspberry Pi 5，ROS 2 Lyrical 已安装，`~/ros2_ws` 已 `colcon build`（至少含 `raspbot_console` 与 `raspbot_bringup` 相关包）。
- 真车模式：底盘/雷达/IMU 的 bringup 链路正常（`/odom`、`/cmd_vel_safe` 有发布者，`/scan` 正常）。
- 网关进程（`console_bridge`）已启动；PC 能 `curl http://<pi>:8080/api/health` 得到 `ok=true`。

### 2.3 首次使用检查清单

1. Pi 上 `curl -s http://127.0.0.1:8080/api/health` → `{"ok":true,...}`。
2. PC 上 `curl -s http://192.168.50.98:8080/api/health`（把地址换成你的 Pi）→ 同上。
3. PC 端打开控制台后顶栏显示「已连接」，ROS 健康为绿。
4. 先用**演示模式**熟悉界面，再上真车。

## 3. PC 端快速开始

### 3.1 演示模式（无硬件，推荐首次使用）

```bat
:: 双击 pc_console\start-demo.bat，或：
cd pc_console
python main.py --demo
```

- 内置 12 m × 8 m 室内仿真场景（0.05 m 栅格，机器人起点约 (1.5, 1.5)），
  协议与 Pi 网关**完全一致**，可完整体验建图/导航/遥控/急停/外设/诊断/日志。
- 默认自动打开浏览器（Edge/Chrome 应用窗口）；不想要窗口用：

```bat
python main.py --demo --no-browser
```

演示模式使用 `pc_console/demo_maps/` 保存地图，不会影响真车配置。

### 3.2 连接真车

```bat
:: 双击 pc_console\start.bat，或：
cd pc_console
python main.py                                  :: 默认目标 192.168.50.98:8080
python main.py --pi 192.168.50.98:8080          :: 显式指定 Pi 地址
python main.py --pi 192.168.50.98:8080 --port 8090 --token <可选token>
```

- 本地控制台默认监听 `127.0.0.1:8090`，浏览器打开 `http://127.0.0.1:8090/`。
- **首次使用请在 UI「设置」里填 Pi 地址/端口/token**：点击顶栏齿轮图标 →
  填 `Pi 地址`（如 `192.168.50.98`）、`端口`（默认 8080）、网关启用 token 时填 `token` →
  点「连接测试」（走 `/local/ping`，显示延迟）→ 保存。配置持久化到 `pc_console/config.json`，
  立即生效，无需重启。
- 常用参数：`--fallback-demo`（启动时探测不到 Pi 自动切演示模式）、`--browser none`（不自动开浏览器）、
  `--port 0`（由系统分配临时端口并打印 URL）、`--verbose`（打印每个 HTTP 请求）。
- **退出 PC 程序不会停止 Pi 上的会话**（设计如此）：Ctrl-C 只关闭本地代理与 UI，
  Pi 侧 ROS bringup / 已下发目标仍继续运行。要停车请先在 UI 停止会话或急停。

### 3.3 启动后应看到什么

顶栏「已连接」+ ROS 健康 + 会话「空闲」；左栏三张模式卡（手动遥控/开始建图/开始导航）；
中间「暂无地图数据」占位（idle 下正常，开始建图/导航后出现地图）；右栏遥测/诊断逐渐有数据。

## 4. Pi 端部署与启动

> 以下都在 **Pi 上**执行（`deploy.ps1` 在 PC 上执行）。脚本细节见 `tools/console/README.md`。

### 4.1 一键部署（PC 上，需能 ssh 到 Pi）

```powershell
pwsh -File tools\console\deploy.ps1
# 等价于：打包 ros2_ws/src/raspbot_console + tools/console → scp → remote colcon build → 纯逻辑单测 → 自检
```

部署完成后 `~/tools/console/` 下会有验收脚本；构建日志在 `/tmp/console_build.log`。

### 4.2 启动网关（二选一，避免双 owner）

**方式 B：网关托管 bringup（调试/台架推荐，PC 上一键启停会话）**

```bash
source /opt/ros/lyrical/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 run raspbot_console console_bridge --port 8080
# 或直接：python3 -m raspbot_console --port 8080
```

**方式 A：附加到 systemd 已启动的真硬件栈（`--attach`）**

```bash
sudo systemctl status raspbot.service        # 确认真硬件栈由 systemd 管理
source /opt/ros/lyrical/setup.bash && source ~/ros2_ws/install/setup.bash
ros2 run raspbot_console console_bridge --attach --port 8080
```

**可选：安装 systemd 服务（开机自启）**

```bash
bash ~/tools/console/install_service.sh --start          # 方式 B：网关托管
bash ~/tools/console/install_service.sh --attach --start # 方式 A：附加外部真车栈
bash ~/tools/console/install_service.sh --uninstall      # 卸载
```

**与 `raspbot.service` 的关系（重要）**

| 方式 | bringup 由谁拉起 | 网关参数 | 网关能否启停会话 |
|---|---|---|---|
| A | `raspbot.service`（systemd） | `--attach` | 否（返回 409，属正常保护） |
| B | 网关（按会话 `ros2 launch` 子进程） | 默认（无 `--attach`） | 是 |

必须二选一。方式 B 前先 `sudo systemctl disable --now raspbot.service`；
方式 A 时不要给 unit 加 `Requires=raspbot.service` 之外的二次拉起。两种方式同时开启会得到
`409 external_stack`（一个 ROS 图一个 owner 的保护），不是故障。

### 4.3 常用网关参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--host` | `0.0.0.0` | 监听地址（只给本机可用 127.0.0.1） |
| `--port` | `8080` | HTTP/SSE 端口 |
| `--token` | 空 | 非空时请求需带 `X-Console-Token`（PC 设置在「设置」里填） |
| `--attach` | 关 | 附加外部 ROS 栈（不管理 bringup） |
| `--maps-dir` / `--maps-fallback` | `/mnt/ssd/maps` / `~/ros2_ws/maps` | 地图保存主目录 / 回退目录 |
| `--max-linear/--max-lateral/--max-angular` | 0.30 / 0.30 / 1.5 | 遥控限幅 |
| `--max-sse` | 4 | SSE 客户端上限（超出 503） |
| `--log-level` | info | 日志级别 |

## 5. 界面区域说明

布局目标 1440×900（最小 1280×720），深色主题：

```
┌──────────────────────────── 顶栏 ────────────────────────────────────────┐
│ 品牌/模式徽章 | 连接状态+延迟 | ROS 健康 | 会话状态 | [急停] | 设置 | 帮助 │
├────────────┬────────────────────────────────────────────┬─────────────────┤
│ 左栏        │ 地图区                                      │ 右栏            │
│ · 会话控制  │  工具条：指针/设目的地/设初始位姿/跟随/回中/  │ · 机器人遥测     │
│ · 地图列表  │         适配/缩放；图层：网格/激光/路径/轨迹/ │ · 导航状态       │
│ · 外设      │         机器人；地图帧/尺寸/版本/坐标        │ · 诊断           │
│            ├────────────────────────────────────────────┤                 │
│            │ 底部：遥控条（WASD/QE/Shift + 虚拟摇杆 + 速度滑杆 + 停止遥控）│
│            │ 底部：事件日志（级别过滤/暂停滚动/会话日志/清空/下载）        │
└────────────┴────────────────────────────────────────────┴─────────────────┘
```

- **顶栏**：品牌与「演示模式」徽章、连接状态与延迟、ROS 健康、会话状态；红色「急停」常驻；
  齿轮「设置」、问号「帮助与快捷键」。ERROR 诊断会出现红色横幅。
- **左栏·会话控制**：idle 时三张模式卡——「手动遥控」「开始建图」「开始导航」
  （导航卡需先用地图列表选一张地图，无地图会提示先建图）；运行中显示当前模式/状态、
  启动进度条、状态文案，「保存地图」「停止会话」按钮。
- **左栏·地图列表**：已保存地图（名称/尺寸/分辨率/预览缩略图）；点击选择地图（导航用）、
  刷新按钮；`valid=false` 的地图置灰不可选。
- **左栏·外设**：蜂鸣器开关、RGB 灯取色/应用/关闭、云台 pan（0–180°）/tilt（0–110°）滑杆与应用。
- **地图区**：滚轮以鼠标为中心缩放、拖拽平移、鼠标坐标实时显示；滚轮/缩放按钮改变比例；
  「跟随」自动跟随机器人，「回中」回到机器人，「适配」整图适配；图层开关控制网格/激光/路径/
  轨迹/机器人的显示。左上显示帧（map/odom）、地图尺寸与版本。
- **底部遥控条**：键盘 W/A/S/D 前后/横移、Q/E 自转、Shift 加速（不超过 limits）；
  键位按下有高亮；虚拟摇杆支持鼠标/触摸，松手回中；速度滑杆显示 m/s；「停止遥控」立即零速。
- **底部日志**：网关 `log` 事件 + 会话日志；按级别过滤、暂停滚动、清空、下载 `.log`。
- **右栏·机器人遥测**：位置 x/y、朝向 yaw、速度 vx/vy/wz、IMU yaw、激光前向/最近距离、数据新鲜度；
  左上角徽章显示定位来源（map=已定位 / odom=未定位）。
- **右栏·导航状态**：阶段文案（等待初始位姿→激活中→就绪→前往目的地→成功/失败/取消）、
  激活进度（步骤 x/6）、剩余距离、已用时间、恢复次数、目的地/初始位姿坐标、导航地图；
  「取消目标」「重新激活」「设初始位姿」按钮；可展开数值输入（x/y/yaw°）直接发目标或初始位姿。
- **右栏·诊断**：OK/WARN/ERROR 计数与最严重消息摘要；「展开全部」查看完整列表；ERROR 时顶栏横幅。
- **模态框**：保存地图（名称校验）、设置（Pi 地址/端口/token、连接测试、图层默认值）、
  帮助（快捷键）、确认（急停解除等二次确认必须点「确定」）——不使用浏览器原生弹窗。

**快捷键**：`V` 指针、`G` 设目的地、`P` 设初始位姿、`F` 跟随、`R` 回中、`0`/`H` 整图适配、
`+`/`-` 缩放、`Esc` 取消当前工具/预览、`WASD/QE` 遥控、`Shift` 加速。

## 6. 建图流程

1. **进入**：确认顶栏「已连接」，点左栏「开始建图」→ 确认弹窗（会提示将停止当前会话并启动建图）。
2. **等待启动**：会话状态变为「运行中」；真实台架首次启动约 10–60 s（界面显示进度与中文状态），
   失败会显示红色错误与原因（可看「会话日志」）。
3. **遥控探索**：用键盘 WASD/QE 或虚拟摇杆缓慢走遍房间；**松手即停**是正常设计；
   地图随扫描实时增长（2 s 内应出现首帧地图）。注意雷达 74 mm 高度的盲区，绕开低矮/玻璃/
   悬空障碍，全程有人监护。
4. **保存地图**：点「保存地图」→ 输入名称（仅字母/数字/下划线/点/短横线，1–40 字符，如
   `room_20261124`）→ 保存。成功后地图出现在「地图列表」；Pi 上产物为
   `<name>.pgm` + `<name>.yaml`（主目录 `/mnt/ssd/maps`，不可写时回退 `~/ros2_ws/maps`）。
   重名会提示 409：换名或（API/脚本）显式 `overwrite=true`。
5. **停止建图**：点「停止会话」等待回到「空闲」。建图模式也会提供遥控，但**不要**在导航模式混淆。

> 地图质量建议：速度档位低、走闭合回路、避免原地快速旋转、避免人员遮挡雷达；
> 贴墙太近会让墙体变厚/缺失，保持 20–40 cm 间距。

## 7. 导航流程

1. **选图**：左栏「地图列表」点击一张已保存地图（卡片高亮，导航模式卡显示所选地图）。
2. **开始导航**：点「开始导航」→ 确认 → 等待会话「运行中」（真实台架 10–60 s）。
3. **设初始位姿**：导航状态提示「请在地图上设置初始位姿」时——
   - 工具条切到「设初始位姿（P）」；在**地图上按住**确定位置、**拖拽**方向确定朝向
     （拖动时显示箭头预览），松开发送；或
   - 右栏「导航状态」展开数值输入，填 `x/y/yaw°` 点「发布」。
   初始位姿要尽量接近车在真实场地中的位置与朝向（不确定时可点地图上机器人实际所在位置）。
4. **等待激活**：网关自动按顺序激活 Nav2（controller/planner/behavior/bt_navigator/collision_monitor），
   界面显示「正在激活导航（步骤 x/6）」。冷启动 20–60 s 属正常，**不要重复点击**；
   失败时显示具体节点与原因，可点「重新激活」重试。
5. **发目的地**：状态变「导航就绪」后，工具条切到「设目的地（G）」，点击地图上的空闲区域
   （灰色/未知区域不可达）；出现目标标记与规划路径，右栏显示剩余距离/已用时间/恢复次数。
6. **结束**：到达显示「已到达目的地」；需要中断时点「取消目标」；失败可看原因
   （`aborted` 常见原因：目标在墙/家具/未知区域内；`canceled` 为手动取消）。
7. **重新定位**：AMCL 跟丢（地图与激光明显错位）时，重新「设初始位姿」——导航中会先取消当前目标，
   再重新激活；不要直接继续跑。

> 导航依赖 AMCL 激光定位；无编码器会导致里程计漂移，长时间/长距离运行后建议重新设初始位姿。

## 8. 遥控与急停

### 8.1 遥控

- 前置：会话 `running`（手动遥控/建图/导航会话均可遥控；导航中首次遥控会确认「将取消当前导航目标」）。
- 键盘：`W/S` 前后、`A/D` 横移、`Q/E` 自转、`Shift` 加速（受 `limits` 限幅）。
- 虚拟摇杆：鼠标/触摸拖动，松手回中并停止。
- **松手即停**：前端松手立即 `POST /api/teleop/stop`；后端 500 ms 看门狗兜底（弱网丢包即停）。
- 速度滑杆显示当前档位（m/s），U 型曲线实际速度受网关 clamp。
- 「停止遥控」按钮立即零速。失焦/切换标签页也会立即停。

### 8.2 急停（软件）

- **锁止**：点顶栏红色「急停」→ **立即锁存，无确认**。后端发布 `/estop=true`、取消导航目标、
  停止遥控、立即零速，并每秒重发一次直到显式解除；界面显示「已急停」红色横幅；
  此时遥控/目标/会话启动全部被拒（409），保留「停止会话」与「解除」。
- **解除**：再点急停按钮 → 弹二次确认 → 点「确定」才解除（防止误触）。
- 真硬件上还有安全链路（`/estop` 诊断项 `Raspbot Safety: E-Stop`），网关启动后会同步真实状态；
  若诊断显示已锁存，UI 会显示急停状态，**不会自动解除**。
- 急停不是「暂停」：解除后不会恢复之前的导航目标，需要重新发目标。

## 9. 外设

会话 `running` 时可用（否则 409）：

| 外设 | 操作 | 说明 |
|---|---|---|
| 蜂鸣器 | 左栏「蜂鸣器」开关 | 发布 `/buzzer`（Bool） |

UI 显示的是「最后命令值」，不读取真实舵机角位置（设计如此）。

## 10. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 顶栏「未连接」/延迟 — | Pi 网关未启动、地址/端口错、防火墙、PC 与 Pi 不同网段 | ① Pi 上 `curl -s localhost:8080/api/health`；② PC 上 `curl http://<pi>:8080/api/health`；③ UI「设置」里核对地址/端口/token 并「连接测试」；④ 用 `--fallback-demo` 先验证 PC 程序本身 |
| 一直 502 `upstream_unreachable` | 代理目标不可达（网关挂了/端口错） | 重启网关；检查 `journalctl -u raspbot-console.service`；确认 8080 未被防火墙拦 |
| 演示模式也没有地图 / 界面空白 | 浏览器缓存、静态资源缺失、`--browser` 未打开 | 刷新 Ctrl-F5；看终端 URL；`python main.py --demo --no-browser` 后手开 URL；确认 `pc_console/web/` 完整 |
| idle 时 `/api/map.png` 404 / 「暂无地图数据」 | 正常：手动/空闲模式没有地图 | 先「开始建图」或「开始导航」；停止会话后地图也会消失（属正常） |
| 导航状态一直「请设置初始位姿」 | Nav2 在等初始位姿 | 用「设初始位姿（P）」在地图上拖拽，或右栏数值输入发布 |
| 「正在激活导航」很久（>60 s）或激活失败 | Nav2 生命周期冷启动慢/节点未就绪/资源不足 | 等待并看激活进度与「会话日志」；点「重新激活」；检查 Pi CPU/内存、`ros2 lifecycle get /bt_navigator` |
| 地图与激光错位（AMCL 跟丢） | 初始位姿不准、场地变化、打滑、雷达被遮挡 | 重新设初始位姿（会先取消目标）；清理雷达窗口；降低速度重建地图 |
| 急停后无法遥控/发目标 | 急停锁存中（设计行为） | 顶栏「已急停」→ 点急停按钮 → 二次确认解除 |
| 急停解除无效 / 状态回跳 | 真实 `/estop` 仍为 true（硬件急停、诊断链异常） | 检查 `/diagnostics` 中 `Raspbot Safety: E-Stop`；排查急停按钮/安全节点；重启网关后仍会同步真实状态 |
| 导航目标 `aborted` | 目标点在墙/家具/未知区域、路径被堵 | 点空闲已知区域；先遥控把附近区域建进地图；看「诊断」与日志原因 |
| 保存地图 409 | 重名（`map_exists`）/ 无地图（`no_map`）/ 会话未运行（`session_idle`） | 换名称；确认建图/导航运行且已收到地图；重试 |
| 端口被占用（`EADDRINUSE` / 启动失败） | 8090 或 8080 已被其它进程占用 | `netstat -ano \| findstr 8090`（PC）/ `ss -ltnp \| grep 8080`（Pi）；换端口 `--port 8091` / `--port 8081` |
| 409 `external_stack` / 双 owner | 网关托管模式遇到已存在的 bringup 栈（或反之） | 二选一：`sudo systemctl stop raspbot.service` 后重试；或网关改用 `--attach`（见 §4.2） |
| SSE 断连（「未连接」+ 地图水印） | Wi-Fi 抖动/网关重启/浏览器休眠 | EventSource 会自动重连（retry 2 s）+ 指数退避；检查网络后刷新；顶栏恢复「已连接」即正常；期间控制禁用是安全设计 |
| 遥控「一顿一停」 | 弱网丢包 → 500 ms 看门狗停车（设计行为） | 靠近 AP/改善 Wi-Fi；不要试图关闭看门狗 |
| 页面按钮灰/提示「导航尚未就绪」 | 前置状态不满足（非 running / 非 ready / 急停） | 看右栏导航状态文案与顶栏；按流程先设初始位姿/解除急停 |
| PC 关了但车还在动/还在导航 | PC 程序退出不会停 Pi 会话（设计） | 先急停或停止会话再退出；必要时 Pi 上 `POST /api/session/stop` 或停网关 |
| 设置里改 Pi 地址提示 409 | 演示模式下不允许改目标（`demo_mode`） | 演示模式无需连接；用真车模式启动（`start.bat`） |

## 11. 已知限制（使用前必读）

1. **无编码器**：`/odom` 开环积分会漂移；导航定位靠 AMCL 激光修正，长距离/打滑后需重新定位。
2. **雷达 74 mm 扫描面**：看不见低矮障碍、玻璃/镜面、悬空物；只有单平面，无 3D 感知。
3. **无悬崖检测**：台阶/桌边不会自动停；禁止在有跌落风险场地运行。
4. **Nav2 生命周期不 autostart**：导航必须先设初始位姿再激活，冷启动 20–60 s。
5. **不提供视频/图传**；不承诺无编码器下的精确走位。
6. **局域网安全**：网关无 TLS/账号体系，token 只是弱防护；仅限可信内网，禁止公网端口映射。
7. **弱 Wi-Fi 下遥控会因 500 ms 看门狗停车**，属安全设计。
8. **演示模式不是物理仿真**：不模拟 Nav2 调参效果、雷达噪声、打滑、电机响应；只用于 UI/协议验收。
9. **单机 SSE 客户端上限 4**（超出 503）；浏览器断线自动重连。
10. **地图名仅限** `[A-Za-z0-9_.-]{1,40}`；保存目录 `/mnt/ssd/maps` 不可写时回退 `~/ros2_ws/maps`。
11. **PC 与 Pi 时钟可能不同**：UI 只用本地接收间隔判断新鲜度，不直接比较两端时间戳。
12. **PC 程序退出 ≠ 停车**：退出前先急停或停止会话。
13. **截图/视觉验收**：深色主题在低亮度屏幕可用；如显示异常请附浏览器版本与截图反馈。

## 12. 安全须知（务必遵守）

1. **有人监护**：任何真车运行（建图/导航/遥控）必须有人在场，手边可随时点急停/断电。
2. **限定场地**：平整室内地面，清除低矮/线缆/玻璃/镜面障碍；有跌落风险处物理围挡。
3. **限速使用**：默认 0.30 m/s；首次上真车用最低档、空旷区域、短距离验证。
4. **急停优先**：异常（乱走、撞墙、定位跳变、失联）第一反应点急停；解除需二次确认。
5. **上电顺序**：先确认底盘/雷达/IMU 正常 → 启动 bringup → 启动网关 → PC 连接 → 才允许发运动命令；
   关机反序：急停/停止会话 → 停 PC → 停网关 → 断 bringup → 断电。
6. **不要让多人同时控制**：同一时间只允许一个浏览器/一个操作者发遥控与目标。
7. **不要修改安全参数**（限速、看门狗、急停链路）用于「跑得更快」。
8. **网络**：只在内网使用；不要把 8080 暴露到公网；token 泄露即换。
9. **电池与散热**：按主 README 电池管理要求执行；异常发热/异味立即断电。
10. **事故留证**：出现异常导航/碰撞，保留「事件日志」下载与 Pi 侧 `~/tools/console/acceptance_sil.sh`
    输出日志，便于复盘。
